# 앱 아이디어 노트 — 타임라인 (Timeline)

- 작성일: 2026-11-24
- 아이디어 제안: 배민우

## 1. 핵심 콘셉트
- 일상생활의 하루하루를 꾸준히 기록해 두고, 시간이 쌓이면 **일생 전체를 하나의 일대기(타임라인)**로 엮어 보여주는 앱.
- 핵심 과제: 사용자가 매일 일일이 쓰지 않아도 **하루의 기록이 자동으로 쌓이게 만드는 방법**.

## 2. 핵심 문제 정의 (21:44 추가)
- 위치·동선 로그만으로는 건조한 '이동 기록'에 그침.
- 목표는 **일생의 스토리(일대기)**를 엮는 것인데, 사용자가 매일 일기 형식으로 길게 쓰지는 않을 것.
- 따라서 **"일기 쓰기 없이도 이야기·감정·맥락이 쌓이는 입력 방식"**이 핵심 차별점.

## 3. 자동 기록 + 스토리화 방식 후보
1. **사진 & 위치 기반 뼈대 자동 생성**
   - 당일 찍은 사진의 시간·위치(EXIF) + OS 저전력 방문 감지(iOS Visit / 지오펜싱)로 기본 뼈대 수집.
2. **백지 대신 '1문장 인터뷰(대화형 회고)'**
   - 앱이 "오늘 신림에 2시간 계셨네요, 무슨 일이셨어요?"처럼 맥락을 짚어 짧은 질문 1~2개를 던지고, 사용자는 카톡 답하듯 5초만 말하거나 입력.
3. **평소와 다른 날(하이라이트)만 캐치**
   - 매일 반복되는 출퇴근 루틴은 자동 요약으로 접어두고, 새 장소·사진 급증·특별한 일정이 있는 날만 "오늘 뭔가 특별한 일 있었나요?" 하고 스토리를 묻는 방식.
4. **원탭 감정·사람 태그 + AI 스토리텔링**
   - 글 대신 기분(뿌듯/피곤/신남)·동행자 태그만 톡 누르면, 쌓인 조각들을 AI가 월간/연간 일대기 문장으로 엮어 줌.
5. **건강·일정·소비 흔적 연동**
   - 캘린더 일정, 걸음 수·수면, 카드 결제 흔적을 보조 단서로 활용.

## 4. 톤 & 자서전 스타일 선택 (21:50 추가)
- 사용자가 처음 시작할 때 **자서전의 톤·분위기(서술 스타일)**를 직접 고름.
  - 예: 친구에게 얘기하는 듯한 편안한 말투, 담담한 에세이 톤, 묵직한 전기/자서전 작가 톤 등.
- 고른 톤에 맞춰 AI가 하루의 조각들을 그 분위기의 문체로 엮어 **한 권의 자서전/일대기**처럼 만들어 줌.
- 하루의 짧은 질문(인터뷰) 말투까지 선택한 톤에 맞추면 '나만의 전속 자서전 작가' 느낌을 줄 수 있음.

## 5. 정보 수집 동의 시 추가 확보 가능 신호 (22:02 추가)
- **건강·컨디션 (HealthKit / Health Connect)**: 수면 시간, 걸음 수, 운동 종류, 심박 변화 → "새벽 3시까지 잠 못 잔 날", "갑자기 15km 걸은 날" 같은 감정·컨디션 단서.
- **음악·콘텐츠 취향 (Apple Music / Spotify / 유튜브 등)**: 그날 반복 재생한 곡이나 최근 빠진 관심사 → 시절별 BGM과 취향 변화.
- **소비·금융·영수증 (마이데이터 / 카드 알림 / 메일 영수증)**: 식사·카페·여행·취미 지출로 구체적 사건 맥락 확보.
- **스크린타임 / 앱 사용 패턴**: 하루 중 집중한 활동(업무·게임·쇼핑 등). 단, iOS는 FamilyControls 권한 제약이 있고 Android(UsageStats)가 상대적으로 자유로움.
- **통화·연락 빈도 (Android 중심)**: 자주 연락하는 사람의 변화(iOS는 통화/문자 접근 불가).
- **날씨·기온 자동 매칭**: 해당 날짜·위치의 날씨를 붙여 장면의 분위기 보강.
- **제외 권장**: 상시 마이크 녹음은 배터리·스토어 심사·거부감 때문에 비추천, 필요 시 짧은 음성 메모 버튼이 현실적.

## 6. 지속 이용(리텐션) 전략 (22:05 추가)
- **단기 보상 루프 (주간·월간 미니 챕터)**: '일생 일대기'는 먼 미래의 보상이라, 매주 일요일 밤 '이번 주 단편'이나 매달 말 '이달의 표지·요약'을 자동 발행해 당장 읽는 재미를 제공.
- **무입력 날도 안 끊기는 구조**: 연속 기록(스트릭) 압박을 주지 않고, 사용자가 답하지 않은 날도 사진·음악·동선·날씨 등 자동 신호만으로 조용히 페이지가 채워지게 설계("오랜만에 열어도 내 기록이 살아있네" 경험).
- **'1년 전 오늘' 회고 알림**: 과거 같은 날의 장면·BGM을 다시 꺼내 주며 자연스럽게 앱 재방문 유도.
- **책이 두꺼워지는 자산감**: "현재 142페이지 · 3장 집필 중" 같은 진행감 + 연말 PDF/실물 자서전 제작 연동으로 쌓인 기록의 가치 체감.

## 7. 확장 설계: 등장인물별 타임라인 & 지인 공유 (22:08 추가)
- **통짜 텍스트 대신 `Event(장면) ↔ Person(인물)` N:M 그래프 모델**
  - 기록을 일기 문자열로만 저장하지 말고 `Scene/Event`(시간·장소·원본 신호) 단위로 쪼개고, 등장인물을 텍스트가 아닌 고유 `Person` 엔티티로 다대다 연결.
  - 추후 실제 가입 유저 계정(`User ID`)과 내 주소록/가상 인물(`Local Person ID`)을 매핑(Link)할 수 있는 구조로 설계.
- **동명이인·호칭/관계 변화 대응**
  - "김대리 → 김과장 → 예전 동료"처럼 시간에 따라 호칭·관계가 바뀌므로 `Person` ID 아래에 기간별 관계/별칭 메타데이터 분리.
- **공개 범위(Visibility)와 시점(POV) 분리**
  - 같은 사건이라도 내 속마음(비공개)과 지인에게 공유할 내용(공개/공동 챕터)을 분리해 저장.
  - 두 사람이 타임라인을 연결할 때 서로의 기억을 덮어쓰지 않고, 하나의 사건을 각자 시점(POV)으로 나란히 참조하는 구조.
- **대규모 시각화 대비 집계 계층**
  - 수년 치 인물·사건 그래프가 커질 것을 대비해 인물별 등장 밀도·기간 요약(챕터) 인덱스 고려.

## 8. 빠른 MVP 제작 추천 스택 & 범위 (22:14 추가)
- **모바일 앱**: **React Native + Expo** (JS/TS 기반이라 웹 프론트 감각으로 가장 빠르게 iOS/Android 동시 빌드 가능. 사진·위치·푸시 알림까지 Expo 모듈로 바로 연동, 향후 HealthKit 등만 네이티브 브릿지 추가). 더 가볍게 웹 기반으로 감싸려면 **Capacitor(Vue)**도 대안.
- **백엔드 & DB**: 가장 빠른 서버리스는 **Supabase(PostgreSQL + Auth + Storage)** — `Event ↔ Person` 관계형 모델링에 적합. 직접 제어하려면 익숙한 **Spring Boot + PostgreSQL** 조합도 빠른 선택.
- **AI 스토리 생성**: 하루 요약 JSON(시간·장소·태그·1줄 답변 + 선택한 자서전 톤)을 LLM API에 넘겨 일기/챕터 생성.
- **MVP 1차 범위(2주 컷)**: HealthKit·결제·지인 공유는 빼고, **① 사진/위치 기반 오늘의 장면 추출 → ② 밤 1줄 인터뷰 → ③ 선택한 톤으로 주간 단편 생성** 3가지만 먼저 구현해 실사용 검증.
